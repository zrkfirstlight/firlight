## 先看一个小问题

如果每个格子只知道自己周围八个格子的状态，一整张网格会怎样变化？康威生命游戏用很少的规则，把这个问题变成了可以观察的实验。这里的“生命”只是模型里的名称，不是在模拟真实生物。

可以先打开[生命游戏实验]({{< relref "/project/life-lab" >}})，按“前进一步”，观察三个横向相邻的亮格如何变成竖向排列。然后再回来理解规则。

## 规则只有邻居计数

一个格子只有亮、暗两种状态。每一代都用**上一代的整张网格**计算下一代：暗格周围恰好有三个亮格时变亮；亮格有两个或三个亮邻居时保留，否则变暗。这通常写作 B3/S23。规则说明可参阅 [LifeWiki 的生命游戏介绍](https://conwaylife.com/wiki/Conway%27s_Game_of_Life)。

重点是“同步”。如果算完一个格子就立即覆盖原值，后面的格子会读到混合了新旧状态的邻居，得到另一个模型。应当准备一张新的网格，全部算完再替换。

{{< fold title="展开：同步更新的伪代码" >}}
```python
for y, x in cells:
    n = count_live_neighbours(old_grid, y, x)
    new_grid[y][x] = n == 3 or (old_grid[y][x] and n == 2)
old_grid = new_grid
```
这里省略了边界检查。本站实验采用有限网格，边界外视为暗格，不把左右两端连接起来。
{{< /fold >}}

## 如何观察

先看稳定的方块，再看周期为二的闪烁条，最后试试滑翔机。不要急着让它快速运行：逐步观察常常更容易知道某个变化来自哪里。本站实验提供这三种预设、单步和暂停，初始不会自动演化。

模型的价值不只是图案漂亮。它让“局部规则”和“整体行为”之间的差别变得可见，也让实现中的同步更新、边界条件有了直观的检查方法。
